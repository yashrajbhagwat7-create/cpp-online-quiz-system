Data Abstraction (Pure Virtual vs Abstract Methods)

Hides the evaluation mechanics behind a unified contract; neither C++ nor C# allows direct instantiation of the base class.

C++ (quiz_system.cpp)
// Abstract Base Class
class Question {
protected:
    int id; string questionText; int points;
public:
    virtual ~Question() {} // Memory safety
    // Pure virtual function (Dynamic polymorphism)
    virtual bool checkAnswer(string userAns) const = 0;
};
C# (.NET Core / QuizWebServer.cs)
// Abstract Base Class in C#
public abstract class Question {
    protected int id;
    protected string questionText;
    protected int points;
    // Abstract method forces derived implementation
    public abstract bool CheckAnswer(string userAns);
}

Hierarchical Inheritance

Derived classes MCQQuestion, TrueFalseQuestion, and FillInBlankQuestion extend common state from Question.

C++ (quiz_system.cpp)
class MCQQuestion : public Question {
    vector<string> options;
    char correctOption;
public:
    MCQQuestion(int id, string t, vector<string> opts, 
                char c, int p)
        : Question(id, t, p), options(opts), 
          correctOption(toupper(c)) {}
};
C# (.NET Core / QuizWebServer.cs)
public class MCQQuestion : Question {
    private List<string> options;
    private char correctOption;
    public MCQQuestion(int id, string t, List<string> opts, 
                       char c, int p)
        : base(id, t, p) {
        this.options = opts;
        this.correctOption = char.ToUpper(c);
    }
}
03

Dynamic Polymorphism & Runtime Dispatch

Processing heterogeneous questions via base references without conditional type branching (no if type == "MCQ").

C++ (quiz_system.cpp)
// Dynamic dispatch via VTable pointer
vector<Question*> questions;
for (Question* q : questions) {
    if (q->checkAnswer(userAns)) { // Runtime vtable
        student.addScore(q->getPoints());
    }
}
C# (.NET Core / QuizWebServer.cs)
// Dynamic dispatch via CLR virtual method table
List<Question> questions;
foreach (Question q in questions) {
    if (q.CheckAnswer(userAns)) { // Runtime dispatch
        student.AddScore(q.Points);
    }
}

Memory Safety: Virtual Destructors vs CLR Garbage Collection

Preventing memory leaks when destroying polymorphic derived objects.

C++ (quiz_system.cpp)
// Explicit Virtual Destructor
virtual ~Question() {} 

// Memory cleanup in QuizManager destructor:
for (Question* q : questions) {
    delete q; // Safely executes derived destructor first
}
C# (.NET Core / QuizWebServer.cs)
// Managed Memory in .NET
// Destructors are not needed for managed types.
// The CLR Garbage Collector (GC) automatically tracks
// generational references and reclaims dead objects.

Top 5 Viva Questions & Fast Answers

Q1: Why is the destructor declared as virtual in C++?

Because when deleting a derived object via a base pointer (delete q;), a non-virtual destructor only frees base slice memory, causing a memory leak. A virtual destructor ensures derived destructors execute first.

Q2: What is the benefit of pure virtual functions (= 0)?

It creates an abstract contract that guarantees any derived question (MCQ, True/False, FIB) must provide its own answer validation logic, preventing accidental empty implementations.

Q3: How does the system handle heterogeneous question types?

Through dynamic polymorphism: storing base references in a collection (vector<Question*> in C++, List<Question> in C#) and letting the vtable dispatch the right method at runtime.

Q4: How does data persistence work across both systems?

Both the C++ console app and .NET web server share the exact same pipe-delimited flat files (questions.txt and results.txt), ensuring 100% interoperability and persistent auditing.
