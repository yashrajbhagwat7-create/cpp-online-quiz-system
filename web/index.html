Object-Oriented Programming Architecture: C++ & .NET C#

Comprehensive technical walkthrough demonstrating how classical C++ object models translate cleanly into modern .NET runtime assemblies.

Curriculum Document CS-204-VIVA
01

Data Abstraction & Pure Virtual Interface Contracts

Both standard C++ and C# enforce interface contracts by disallowing base instantiation and mandating derived implementations.

C++ Architecture (quiz_system.cpp)
// Abstract Base Class with Pure Virtual Method
class Question {
protected:
    int id; string questionText; int points;
public:
    virtual ~Question() {} // Memory safety
    // Pure Virtual Function (= 0)
    virtual bool checkAnswer(string userAns) const = 0;
};
C# .NET Architecture (QuizWebServer.cs)
// Abstract Base Class with Abstract Method
public abstract class Question {
    protected int id;
    protected string questionText;
    protected int points;
    // Abstract Method enforced by compiler
    public abstract bool CheckAnswer(string userAns);
}
02

Hierarchical Inheritance & Specialized Question Modalities

Concrete subclasses inherit base attributes (id, text, points) while encapsulating their individual response representations.

C++ Architecture
class MCQQuestion : public Question {
    vector<string> options;
    char correctOption;
public:
    MCQQuestion(int id, string t, vector<string> opts, 
                char c, int p)
        : Question(id, t, p), options(opts), 
          correctOption(toupper(c)) {}
};
C# .NET Architecture
public class MCQQuestion : Question {
    private List<string> options;
    private char correctOption;
    public MCQQuestion(int id, string t, List<string> opts, 
                       char c, int p)
        : base(id, t, p) {
        this.options = opts;
        this.correctOption = char.ToUpper(c);
    }
}
03

Dynamic Polymorphism & Runtime VTable Resolution

Heterogeneous question evaluation without brittle conditional type-checking (no if (type == "MCQ")).

C++ Dynamic Dispatch
// Runtime dispatch via VTable pointer
vector<Question*> questions;
for (Question* q : questions) {
    if (q->checkAnswer(userAns)) { // VTable lookup
        student.addScore(q->getPoints());
    }
}
C# Dynamic Dispatch
// Dynamic dispatch via CLR virtual dispatch
List<Question> questions;
foreach (Question q in questions) {
    if (q.CheckAnswer(userAns)) { // MethodTable lookup
        student.AddScore(q.Points);
    }
}
04

Memory Lifecycle: Virtual Destructors vs CLR Garbage Collection

Contrasting manual resource destruction with managed generational garbage collection.

C++ Explicit Cleanup
// Explicit Virtual Destructor
virtual ~Question() {} 

// Safe polymorphic destruction:
for (Question* q : questions) {
    delete q; // Calls derived destructor first
}
.NET Automatic GC
// In C# .NET:
// Managed types do not require explicit destructors.
// The CLR Generational Garbage Collector (Gen 0, 1, 2)
// automatically cleans up unreferenced objects.

Standard Viva Voce Examination Questions

Key theoretical and implementation questions commonly posed by university laboratory examiners:

Q1

Why is declaring a virtual destructor essential in C++ when using polymorphism?

When deleting a derived object via a base pointer (delete q;), if the destructor is not virtual, only the base class destructor is invoked. The derived class destructor never runs, causing resource and memory leaks.

Q2

What is the difference between early binding and late binding?

Early (static) binding resolves function addresses at compile time. Late (dynamic) binding determines which method to call at runtime via the object's Virtual Method Table (VTable), enabling true polymorphism.

Q3

Can an abstract class have constructors in C++ and C#?

Yes. Although an abstract class cannot be instantiated directly, its constructor is executed by derived class constructors to initialize base member variables (such as id, questionText, and points).

Q4

How do the C++ and .NET implementations maintain shared state?

Both applications interoperate directly over shared flat-file streams (questions.txt and results.txt) using standardized delimited serialization, allowing cross-platform persistence without proprietary database engines.
